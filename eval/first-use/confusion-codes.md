# Confusion codes

A confusion is a moment where the person is stuck, does the wrong thing,
or says they are unsure, about one of the things below. Log one entry each
time it happens, with the task it happened in. Code what you **see or
hear**, not what you guess they were thinking.

Use the code in the `code` field of the sheet exactly as written.

| Code | Log it when the person… | Examples of what you might see |
|---|---|---|
| `mic_state` | is unsure whether the app is listening, or acts as if it is listening when it is not (or the reverse) | talks while nothing is listening; asks "is it on?"; taps the microphone again and again; stops talking because they think it stopped |
| `what_to_say` | knows how to talk to it but not what to say, or how much | long silence after it is listening; asks "what should I say?"; asks if they should speak in a certain way |
| `where_memory_is` | cannot find where the app shows what it kept | opens screens at random during Task 2; asks "where would that be?"; looks in settings or privacy screens for it |
| `correction_path` | has found the wrong thing but cannot work out how to change it | looks for an edit button that is not there; tries to tell it out loud and is unsure it worked; gives up on the change |
| `permissions` | is stopped or unsure because of a system prompt (microphone, notifications) | hesitates over the microphone prompt; denies it and is then stuck; asks what the prompt means |
| `other` | is confused in a way none of the codes above covers | anything else; you **must** add a short `note` (140 characters or fewer) saying what it was, in your words, without quoting what they said about their own life |

## Rules

- One entry per moment. If the same confusion comes back later in the
  session, that is a second entry.
- The `task` field says when it happened: `setup` (before Task 1),
  `talk`, `find`, `correct`, or `checks` (during the comprehension
  questions).
- Notes describe behaviour ("tapped mic 4 times, then asked if it was
  broken"). Never write what they talked about.
- If you are unsure whether something counts, it does not. Under-counting
  is safer than inventing confusions.
- If `other` comes up for the same thing with two or more people, raise it
  with the owner after the study as a possible new code. Do not add codes
  in the middle of the study: every session must be coded against the same
  list.

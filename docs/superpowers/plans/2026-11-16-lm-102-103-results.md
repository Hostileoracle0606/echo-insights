## Rulings and decisions

- Local pgTAP ran against the local Supabase container (127.0.0.1:55322), using `supabase migration up --local` and `db reset --local`. Never a hosted project.
- Unmerged migrations `000100` and `000200` were edited in place (they exist only on this branch).
- Draft cards never claim the card key (found in Task 1; the first version would have blocked the final card).
- Entity-only notebooks stay in the unfinished-cards list; the client treats a 422 `nothingToSummarize` as terminal per `(notebook, revision)` and remembers it locally.
- The headless finisher defers rather than drops on failures; a journalled turn is never dropped on `notFound` (shared phones); bounded recovery commits with an empty patch so words are kept.
- The final batch of an erase job deletes the job and ledger, so a replay of the very last batch returns "finished, 0 rewritten".
- A session opening a notebook during a catch-up turn step can duplicate work for at most one step; keyed commits make it safe (documented in `catch_up_provider.dart`).

## Left undone / for later

- **Vectors are not built by the phone.** Catch-up records "server catches up"; the 15-minute `embed-reconcile` cron builds them. Case 4 simulates that sweep. Under Phase 3 this must move to the device (LM-95).
- **Case 5 copy:** phone A's unsynced local turns are lost; the copy saying so belongs to LM-89 / LM-110.
- **Crashed notebooks** keep `ended_at` null and read "live now"; catch-up finishes the card but does not end the notebook.
- **Force quit during the card call** costs one extra model call (the killed call is paid, never saved).
- **Deploy order:** apply migration `20261116000050` before deploying the close-session Lambda (it selects `is_draft`).
- Replace on a changed vector is delete then insert (not atomic); the sweep recovers a crash in between.
- Under encryption, card payload hashes over ciphertext will differ on retry; the result is `keyReused`, which every client treats as done.
- `infra/test/infra.test.ts` (jest) needed `npm ci` in `infra` (node_modules is ignored by git).
- One unexplained single flake was seen once in a full `flutter test` run, not reproduced.
